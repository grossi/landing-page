Game audit — 2026-09-05

Scope: all nine standalone HTML experiences under `public/arcade`, the routed EPHEMERIS experience, the DEEP FIELD landing experience, and their shared engine/tests. This was an audit; no game implementation or tests were changed.

Validation: `npm test` passed 346 tests across 25 files in 6.03 seconds. `npm run build` passed, with Vite's size warning for the 521 kB minified Three.js chunk. The standalone HTML scripts are copied from `public`; passing the TypeScript build does not validate their gameplay. Small Node harnesses executed the actual inline scripts against the vendored Three.js, with DOM/rendering stubs. These verify simulation logic and disposal calls, not rendered appearance, GPU memory growth, or browser FPS. CPU timings below are local Node measurements, not device-wide performance promises.

1. **High — HYPERTUNNEL can skip collisions on slow frames.** [Collision check](../public/arcade/tunnel/index.html#L169). Obstacles are moved before testing whether their new Z lies within a 1.6-unit band around the player. At the maximum speed of 95 units/s, a 50 ms step moves 4.75 units. Reproduction: obstacle at Z = -13, player Z = -12, gap facing away from the player, speed 95, then `tick(50)`. The obstacle ends at -8.25 with `hit: false` and the game still in `play`. This also becomes possible at ordinary 30 FPS. Test the swept crossing using previous/current Z, with steering interpolated or substepped where needed. Add a regression for crossing the entire band in one frame. The camera roll at line 181 also uses a fixed `0.016` instead of `dt`, making its response refresh-rate dependent.

2. **High — MONOSTACK abandons per-block materials.** [Block creation and reset](../public/arcade/stack/index.html#L67), [falling-piece removal](../public/arcade/stack/index.html#L204). Every block creates a Lambert material and an identical line material. Reset and falling-piece retirement only remove objects from the scene. A reset harness observed four retired material instances and zero disposal events. Dispose owned materials on both removal paths and share the identical edge material. Keep the shared box/edge geometries alive. Long runs also retain every historical stack block; retain logical height/top state separately and retire blocks far below the view. Verify renderer resource behavior in a browser after repeated play/retry cycles.

3. **High performance priority — EPHEMERIS builds its most expensive topology outside the job budget.** [Synchronous table request](../src/engine/lod/lodManager.ts#L614), [table construction](../src/engine/lod/icosphere.ts#L142). `requestLevel` calls `getIcosphereTables` before enqueueing displacement work. A cold level-6 request synchronously subdivides meshes, deduplicates edges, and allocates tables. Nine fresh-module trials measured 18.54–27.89 ms, median 21.49 ms, for that call alone. The 3 ms displacement budget cannot contain this hitch. Move topology generation into a worker or resumable preparation stage, or load precomputed tables. Merely calling it earlier in another animation frame still blocks that frame. It is memoized, so this is a first-use cost, not a steady-state 21 ms/frame cost.

4. **High performance priority — MERIDIAN repeatedly rebuilds unchanged terrain.** [Terrain loop](../public/arcade/meridian/index.html#L166). Outside THE SEA and biome crossfades, height depends only on world coordinates. The snapped terrain origin often remains unchanged across multiple frames, yet all 4,225 vertices are sampled and marked for upload every frame. A 60-frame harness in THE RANGES recorded 253,560 height evaluations, including the 60 ship-ground samples, with only six grid-origin changes. Rebuilding only when that grid changes would cut terrain evaluations by 90% in this scenario. Continue updating the terrain transform each frame; keep per-frame height updates for the animated sea and crossfades. Hoist biome selection/blend calculation out of the vertex loop. OPEN HORIZON's terrain also resamples all 3,445 vertices per playing frame, but its continuously changing sample coordinates require a chunk/row-streaming design or shader displacement, not the same simple cache.

5. **Medium — VOID FIELD processes terminal death more than once.** [Asteroid collision loop](../public/arcade/asteroids/index.html#L272), [die](../public/arcade/asteroids/index.html#L151). On the last life, `die()` changes state without resetting invulnerability or exiting the asteroid loop. Two overlapping asteroids at one remaining life produced `state: 'over'`, `lives: -1`, and 28 shards in one tick. Exit collision processing when death becomes terminal, or guard it on play state. Add a single regression for simultaneous terminal collisions.

6. **Medium — standalone input can stick after focus loss or canceled touches.** For example, [DRIFT input](../public/arcade/drift/index.html#L161). The standalone scripts set key/pointer/touch state on down/start and clear it only on up/end; none has a blur, pointer-cancel, or touch-cancel handler. Releasing outside the browser can leave steering, firing, or boost active on return. Use the same reset-on-blur policy already present in the shared engine and clear touch state on cancellation. This is a source-level finding; OS focus-loss behavior was not browser-tested.

7. **Medium performance opportunity — the geometry queue creates work it immediately discards.** [Queue update](../src/engine/lod/geometry.ts#L364). Each update sorts a snapshot and creates a closure for every remaining slice of every job, even if only a few slices fit the budget. The remainder is discarded and recreated next frame. A new level-6 job creates 41 closures on the first update alone. Iterate jobs/slices directly or retain a resumable queue, preserving priority changes and cancellation. Include sorting/preparation in the elapsed-time budget. Allocation reduction is established by the code; FPS impact was not measured.

8. **Medium performance opportunity — merge simple line batches before attempting a large renderer rewrite.** [MURMUR grid](../public/arcade/murmur/index.html#L93) creates 34 individual lines with one material; [GRID CITY grid](../public/arcade/city/index.html#L96) creates 27. Each grid can be one `LineSegments` geometry, reducing the maximum visible submissions from 34/27 to one. DRIFT's 110 rocks share three geometries and one material and are candidates for three instanced batches, keeping collision state separate. GRID CITY buildings can similarly batch faces/edges, but that change is larger. Measure visible draw calls before and after. MURMUR already samples only seven neighbors per bird: its flock loop is O(N), not all-pairs O(N²), so a spatial-index rewrite is not automatically a performance win.

9. **Low — remove obsolete wrappers and an unused API barrel.** [FOV wrappers](../src/engine/core/flight.ts#L265) `easeFov` and `updateFov` have no live game caller; the games now use `easeFovValue` through their current camera/rig paths. They survive through exports and tests. Remove them and their wrapper-only tests, preserving scalar FOV and live rig behavior coverage. [isPaused](../src/engine/render/stage.ts#L27) only returns `sources.size > 0`; inline it at its single production call and replace its three predicate tests with stage pause/resume lifecycle coverage. The large [engine barrel](../src/engine/index.ts) has no production importer in this repo; its test is its consumer. Either remove it or deliberately retain a small public API. `ICO_ULTRA` in assets is also unused outside that barrel. Keep helpers that enforce actual ownership or shared policy, including resource tracking, listener cleanup, `wireMat`, and the flight rig; short functions are not inherently wasteful.

10. **Low — delete no-op effects and small hot-loop allocations.** [MONOSTACK pulse loop](../public/arcade/stack/index.html#L206) computes an unused scale and multiplies `scale.x` by one. `pulse()` only feeds that ineffective work. Remove the entire effect or implement it, and remove unused `dir` and the unused spawn-height calculation. [MURMUR scatter](../public/arcade/murmur/index.html#L216) eases a scalar that nobody reads. DRIFT, MURMUR, and legacy EPHEMERIS allocate an Euler and camera-offset Vector3 each frame; use stable scratch objects or `tmp.set(...)`. Most standalone HUDs also rewrite unchanged labels every frame: update counters on change and throttle distance/time text. These are smaller wins than topology and terrain work.

11. **Test maintenance — keep the useful invariants, reduce assertion overhead.** [Icosphere edge test](../src/engine/lod/icosphere.test.ts#L49) took 3.365 seconds; the whole file took 4.217 seconds and was the slowest suite. The edge test executes four matcher calls for each of 163,800 edges across six levels. The invariant is valuable; the matcher volume is not. Scan with plain comparisons, retain the first offending level/edge, and assert once per invariant/level. Apply the same pattern to the unit-vector loop, which took 678 ms. [Barrel tests](../src/engine/index.test.ts#L9) mostly check exported function types and exact tuning constants; replace with a minimal import-safety smoke test only if that public API remains. [FOV wrapper tests](../src/engine/core/flight.test.ts#L365) protect unused paths. The actual LOD, cache pinning, disposal, deterministic-world, and flight behavior tests should remain.

12. **Coverage and architecture — the standalone games are outside the tested engine.** The 346 passing tests include engine/post tests, not the standalone games or complete DEEP FIELD/EPHEMERIS orchestration. Prioritize start → play → game-over → retry, canceled input, low-frame-rate collision, disposal, and transition reversal checks over more exported-constant assertions. The old [static EPHEMERIS](../public/arcade/ephemeris/index.html) is still shipped despite the arcade card linking to the newer `/ephemeris` route; redirect the old URL if the legacy experience is no longer intended. Share a small standalone lifecycle/input/HUD module where useful, rather than automatically porting every prototype into the full space engine.

One profiling question remains: [the shared quality governor](../src/engine/render/stage.ts#L163) measures JavaScript and render submission time, not GPU completion or missed presentation deadlines. It may fail to reduce DPR in a GPU-bound scene. Confirm with a browser GPU/CPU trace before changing its policy; combine presentation cadence or asynchronous GPU timing with the existing CPU measure, accounting for display refresh and paused tabs. No GPU speedup is claimed by this audit.

Suggested order: fix the collision, disposal, and terminal-death bugs; eliminate redundant MERIDIAN work and cold topology hitches; simplify expensive tests and dead code; then profile batching and governor behavior on actual target devices.
